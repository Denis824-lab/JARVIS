# Анимации JARVIS и бриф для After Effects

Редакция 2026-10-03. Владелец готов создавать анимации сам. Это спецификация для совместного прототипирования; файлы и финальные длительности ещё не утверждены.

## Художественная цель

Активация ощущается как появление внимательного помощника: ядро собирается, мягко проявляется свет/контур, короткий звук подтверждает связь. Запуск приложения — выразительная короткая композиция, переходящая в реальное окно. Выбранное движение, палитра и форма должны быть едиными с основным интерфейсом.

Два слоя: заранее созданная художественная анимация и динамическая индикация состояния/звука. Первый придаёт характер, второй доказывает, что микрофон принимает речь и система делает конкретное действие. Они могут быть визуально объединены, но технически управляются отдельно.

## Набор композиций

| Имя | Сценарий | Стартовый диапазон для пробы | Поведение |
|---|---|---|---|
| `app_launch` | Явное открытие основного приложения | 1,2–2 s | Один показ, переход в окно; пропуск и настройка отключения |
| `wake_intro` | Голос/горячая клавиша | 350–650 ms | Появление ядра и переход в listening без паузы |
| `listening_base` | Микрофон действительно захватывает | Спокойный цикл 1–2 s | Поверх него реальная амплитуда/уровень, текст «Слушаю» |
| `processing_loop` | Запрос обрабатывается | Цикл 1–2 s | Отличается от listening; нет фальшивого процента готовности |
| `executing_loop` | Выполняется инструмент | Цикл 1–2 s | Текст конкретного действия поступает из runtime |
| `speaking_base` | Реально воспроизводится ответ | Динамическое состояние | Реакция на выходной звук, прекращается при остановке |
| `confirmation` | Нужна авторизация | Статичный/медленный вид | Сохраняется до решения; не выглядит как выполненное действие |
| `success_outro` | Проверенный успех | 300–600 ms | Мягкое завершение без перекрытия следующей просьбы |
| `error_outro` | Ошибка/частичный результат | 400–800 ms | Короткий акцент; объяснение остаётся читаемым |
| `sleep_exit` | Завершение разговора | 200–400 ms | Уходит, освобождает ресурсы |

Это исходные параметры, а не обязательный хронометраж. Длинные исследования не заставляют анимацию постоянно потреблять GPU. Успех показывается только после результата инструмента.

## Приоритет поведения

Микрофон начинает захват без ожидания окончания wake-анимации. Пока разрешение/устройство недоступны, не показывать готовое «Слушаю»; обозначить проблему. Для критического статуса есть мгновенная простая индикация, даже если художественный файл ещё загружается.

Запуск UI не блокирует ядро или исполнителя. Не проигрывать полноэкранное intro при каждой автозагрузке ОС/активации голоса. Повторный вызов, «стоп», новая просьба и ошибка могут прервать текущий клип. Статусы имеют приоритет над длительностью ролика. В покое/скрытом окне render loop остановлен.

## Что подготовить владельцу

1. Storyboard 6–10 ключевых кадров: запуск, появление, слушание, обработка, речь, завершение/ошибка.
2. Для первой пробы — квадратная композиция ядра примерно 512×512 и запуск под согласованный размер окна. Прозрачный фон для overlay, запас вокруг glow без обрезания.
3. 30 fps как экономичный старт; 60 fps вариант только после сравнения на ноутбуке/игровом ПК. Параметры не являются доказанным лимитом.
4. Раздельные intro, loop и outro с совместимыми граничными кадрами; перечисленные имена композиций, длительность, маркеры переходов и версия.
5. Не запекать изменяемые тексты, проценты и русский транскрипт в ролик. Текст/кнопки рисует приложение, поэтому они доступны, масштабируются и не отстают от состояния.
6. Отдельные звуки, если они есть, с указанным событием. Не зашивать громкое приветствие в каждый visual clip.
7. Передать `.aep`, нужные ресурсы/лицензии и preview. Платные плагины обозначить; предпочтительно иметь вариант без обязательного платного runtime.

## Экспорт после технической пробы

Простые векторные слои: Lottie/Bodymovin как кандидат. Экспортёр поддерживает лишь часть After Effects; сложные эффекты и 3D нельзя считать автоматически переносимыми. Сначала экспорт короткого образца и сравнение с AE в целевом renderer. Источник: [Lottie After Effects](https://airbnb.gitbook.io/lottie/after-effects).

Сложное свечение/частицы: прозрачный видеоклип или другой заранее отрендеренный ресурс после проверки декодирования/alpha в Windows WebView2 и Linux WebKitGTK. WebM с alpha — кандидат, не гарантия одинакового результата. PNG sequence удобна как промежуточный master, но может дорого расходовать RAM/диск; не грузить её целиком без оценки. Для простого устойчивого fallback — программный контур/состояние.

Живой аудиослой реализуется отдельно: ограниченная частота обновления, сглаженный уровень/спектр, отпускание после звука; он не угадывает время речи по длине текста. Один монолитный ролик для всех состояний исключён.

## Визуальная и техническая приёмка

Сравнить AE-preview и runtime: форма, цвет, alpha, скорость, отсутствие обрезки и скачка на стыке. Проверить холодный/повторный запуск, длительную тишину, громкую речь, отключённый микрофон, игру/музыку, прерывание и несколько мониторов. Масштабы 100/125/150/200%, тёмные/светлые окна позади.

Измерить CPU/RAM/GPU/frame time на обоих устройствах. Reduced motion заменяет эффект коротким переходом/статичным состоянием, но сохраняет признак прослушивания. При недоступном медиа-файле приложение остаётся управляемым. Настройки: запуск, уровень motion, звуки и положение overlay.
