# Архитектура — облачное ядро, заменяемый стек

Облачное ядро подтверждено владельцем 2026-10-03. Стек предварительный. Полностью локальная система исключена из текущего плана.

## Общая схема

```text
Владелец ↔ Desktop UI / голос
                  ↓
           локальный маршрутизатор
            ↙                 ↘
    точная локальная       облачное ядро
        команда          память / LLM / расписание
            ↖                 ↙
             план инструментов
                    ↓
             проверка политики
                    ↓
          исполнитель нужного устройства
                    ↓
           проверка результата / журнал / ответ

Почта и другие источники → события → правила → уведомления
```

LLM — заменяемый планировщик и собеседник. Модель не является хранилищем памяти, системой прав, таймером или источником истины о выполненных действиях.

## Три части

**Приложение.** Текстовый диалог, голосовые состояния, настройки, просмотр памяти и действий. Закрытие окна не обязательно останавливает исполнителя: такое поведение должно быть явно настроено и отображено.

**Локальный исполнитель.** Регистрация устройства, инструменты ОС, файлы, процессы, браузер, микрофон, локальные STT/TTS, очередь offline. Предлагается отдельный управляемый процесс, который не зависит от перерисовки окна. Локальное IPC требует аутентификации и ограничения доступа текущим пользователем; не открывать публичный порт. Модельные аудиодвижки могут быть дочерними процессами с лимитами и контролем завершения.

**Облачное ядро.** Главная долговременная память, учёт устройств, синхронизация небольших записей, API модели, расписание, инициативность и источники событий. Домашний компьютер выполняет локальные действия, может обрабатывать аудио и управлять своей браузерной сессией. Serverless не считать обычным постоянно работающим Linux-сервером. Ядро входит в первый полезный выпуск.

При выключенных устройствах доступны облачные функции и уведомления на подключённый телефонный канал. Окно на выключенном устройстве открыть нельзя. Удалённый браузер, личный Telegram-клиент и постоянный IMAP могут потребовать дополнительного облачного runtime: проверить до обещания бесплатного полного набора. Команду «открыть сейчас» не сохранять до произвольного включения ПК без согласованного сценария и срока.

## Предварительный стек и развилки

| Часть | Кандидат | Причина и условие решения |
|---|---|---|
| Desktop | Tauri 2 + TypeScript + React + Vite | Системный WebView, отдельная граница native/UI; проверить overlay и ограничения конкретного Linux/Wayland |
| Native/исполнитель | Rust; Python sidecar только при необходимости | Rust подходит для фонового процесса и Tauri; Python легче для ряда библиотек, но добавляет упаковку и второй runtime |
| Облако | TypeScript, Cloudflare Workers + D1 + Cron | Небольшой личный сервис с бесплатным стартом; проверить доступность из сети пользователя и реальные ограничения |
| Связь устройств | Исходящий HTTPS сначала; WebSocket/SQLite Durable Object при необходимости | Сначала измерить задержку и цену; не добавлять постоянную инфраструктуру автоматически |
| Локальные данные | SQLite | Локальная очередь, кэш, полнотекстовый поиск; резервное копирование и миграции |
| STT | whisper.cpp, профиль модели после замеров | Кандидат для локального распознавания; скорость и качество русского проверить на железе владельца |
| TTS | Piper как лёгкий кандидат + сравнение иных локальных движков | Выбор зависит от прослушивания, ресурсов и лицензии каждой модели |
| LLM | PlusVibe, адаптер и список дешёвых резервов | Прайс/документы изучены; реальные возможности, задержка и счёт ещё не проверены |
| Браузер | Выделенная сессия автоматизации, API сервисов в приоритете | Не извлекать пароли и cookies из всех профилей; поддержку конкретного кабинета проверить отдельно |

React здесь кандидат, а не необходимое условие. Не добавлять Next.js, Kubernetes, брокер сообщений, векторную БД и агентный framework без конкретной необходимости. Число языков и процессов ограничиваем, чтобы владелец мог сопровождать проект.

## Известные устройства

| Устройство | Установка ОС | Железо | Особенности |
|---|---|---|---|
| Игровой ПК | Windows 11 | Core i5-11400F, RX 580, 16 GB RAM 3200 | Уменьшать нагрузку во время игры; VRAM не указана |
| Рабочий ноутбук | Windows 11 | Ryzen 7 5825U, 16 GB RAM | Основное устройство; дискретная GPU не заявлена |
| Тот же ноутбук | Zorin OS, отдельный SSD | То же железо | Dual boot: одновременно работает одна установка |

Две физические машины, до трёх регистраций исполнителя. Каждой ОС свой токен/ID; связь с одним ноутбуком не разрешает автоматически читать другой SSD. Первые STT/TTS-пробы в CPU-режиме; затем проверять поддерживаемое ускорение. Не делать обязательный CUDA-путь для этих устройств. Облачный TTS тоже кандидат: выбор по качеству, цене и задержке.

## Путь команды

1. Ввод получает `request_id`, источник и устройство. Голос превращается в текст локально, если выбран локальный режим.
2. Точная безопасная команда идёт в обычный обработчик. Неуверенный разбор не превращается в случайный запуск: модель или уточнение.
3. Для сложной задачи извлекаются небольшие релевантные данные; выделяется лимит шагов, времени и денег.
4. План состоит из структурированных вызовов инструментов. Неподдерживаемый инструмент не исполняется как произвольный код.
5. Policy engine проверяет вызовы; локальный исполнитель повторно проверяет права, параметры, устройство и срок.
6. Инструмент возвращает фактический статус. Неопределённый исход обозначается как неизвестный, а не как успех или повод повторить изменяющее действие.
7. Ответ опирается на результат. В журнал записываются понятные этапы, расходы и ошибки без секретов.

Сложную задачу координирует облако; точные локальные команды могут обойти сеть. При отказе маршрута модельный резерв получает подтверждённое состояние; уже выполненные инструменты не повторяются. Межмодельная история нормализуется без несовместимых сырых reasoning-блоков.

Терминал — отдельный инструмент с явной оболочкой, рабочей папкой, окружением, лимитом времени/вывода и контролем дерева процессов. Он не заменяет безопасные специализированные инструменты.

## Память и переносимость

Данные разделены: профиль, подтверждённые факты, заметки, задачи, события, предпочтения, сведения о проектах. Запись хранит идентификатор, происхождение, даты, уровень чувствительности и состояние подтверждения. Предположение модели не становится подтверждённым фактом.

Начало: структурированные запросы и полнотекстовый поиск. Семантический поиск добавляем при измеренном недостатке обычного; индекс можно пересоздать из исходных записей. Историю обрезаем для контекста, но не удаляем данные без политики хранения.

Предложение: облако — основное хранилище небольших синхронизируемых данных; локально — кэш, очередь и большие файлы/аудио/скриншоты, если не разрешена загрузка. Чувствительная память: сервер читает разрешённые поля для фоновых функций либо end-to-end шифрование с расшифровкой на устройстве. Нельзя одновременно обещать непрозрачность облаку и свободный облачный смысловой анализ тех же данных. Режим ещё выбирается.

## Синхронизация и надёжность

- Локальная запись и outbox фиксируются одной транзакцией. Отправка имеет `operation_id`; получатель дедуплицирует повторы.
- Обновления используют версию записи; удаления — tombstone. Конфликт личной записи не теряет текст молча: сохраняются версии и показывается выбор.
- Команда устройства содержит идентификатор, цель, тип, версию протокола, параметры, срок, основание разрешения и статус. Просроченную/повторную команду отвергать.
- Серверная доставка не равна выполнению. При неопределённом исходе требуется проверка, особенно для сообщений и файлов.
- Offline-действия доступны в рамках локальных прав. Облачные функции показывают недоступность; очередь не запускает неожиданно опасное действие после восстановления сети.
- Напоминание хранит срок, временную зону и статус доставки. Минутный планировщик подходит для приблизительных напоминаний; точный секундный таймер выполняется локально. Сбой канала требует повторной доставки и дедупликации.
- Резервные копии шифруются; восстановление проверяется на чистом тестовом профиле. Облачная синхронизация не заменяет резервную копию.

## Долгосрочное сопровождение

Миграции версионируются, протокол допускает обновление устройств не в один момент, экспорт сохраняет записи и связи в документированном формате. Обновления приложения проверяются перед установкой, поддерживается откат. JARVIS может предложить изменение своего кода, но не устанавливает его бесконтрольно.

Источники для выбора кандидатов: [Tauri architecture](https://tauri.app/concept/architecture/), [Tauri security](https://tauri.app/security/), [whisper.cpp](https://github.com/ggml-org/whisper.cpp), [Piper](https://github.com/OHF-Voice/piper1-gpl), [Cloudflare Workers](https://developers.cloudflare.com/workers/platform/pricing/). Проверено чтением официальных источников 2026-10-03; никаких локальных бенчмарков пока нет.
