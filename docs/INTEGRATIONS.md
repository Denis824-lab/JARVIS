# Универсальные возможности и подключения

Цель — помощник для разных задач владельца. Яндекс Игры, почта и Telegram — примеры использования общей системы. Этот документ описывает проектирование; реальные аккаунты ещё не подключены.

## Общая основа

Каталог инструментов сообщает: назначение, поддерживаемое устройство, права, статус подключения, схему параметров, лимиты и способ проверки результата. Модель получает только подходящие инструменты для задачи, а не огромный список всех интеграций.

Порядок способов: документированный API → системная функция/структурированные данные → разрешённая браузерная сессия → анализ экрана и UI-управление при необходимости. Не все сервисы имеют нужный API. Успешный вход в браузер не означает устойчивой автоматизации любого действия.

При неожиданной просьбе: определить нужный источник и действие; проверить подключения/права/свежесть; выбрать доступный способ; выполнить в рамках бюджета или объяснить конкретно, чего не хватает. Неподключённый сервис нельзя заменить выдуманным ответом. Установка нового расширения/кода не происходит скрыто.

## Gmail и Яндекс Почта

Владелец указал основной Gmail и важный Яндекс-ящик. Точные адреса оставляем в приватной конфигурации. Каждому аккаунту своя идентичность, токен и состояние sync; уведомления сохраняют указание источника.

Gmail: официальный API, OAuth с минимальным чтением; уведомления через Pub/Sub либо ограниченный опрос. `watch` нужно обновлять до истечения, минимум каждые 7 дней; push сообщает историю изменения, затем API получает подробности. Проверять пропуски и полную повторную синхронизацию. Источник: [Gmail push](https://developers.google.com/workspace/gmail/api/guides/push).

Яндекс: официальный IMAP с OAuth; документация описывает read-only `mail:imap_ro`. Проверить доступ для конкретного личного ящика, регистрацию приложения, разрешения и работу runtime. Способ: ограниченный опрос либо постоянный адаптер, если оправдан. Источники: [OAuth](https://yandex.ru/support/yandex-360/business/mail/ru/web/security/oauth), [настройка клиентов](https://www.yandex.ru/support/yandex-360/customers/mail/ru/mail-clients/others).

Исходящие/входящие связываются по service thread ID либо `Message-ID`/`In-Reply-To`/`References`; одинаковая тема недостаточна. AI нужен для смысловой оценки только после дешёвых правил. Чтение, подготовка черновика и отправка — разные права.

## Telegram: два разных подключения

Бот удобен для общения с JARVIS и доставки уведомлений. Он получает адресованные ему сообщения и доступные ему группы; не читает произвольно личные диалоги владельца. Источник: [Bot FAQ](https://core.telegram.org/bots/faq).

Для «кто мне писал?» нужен пользовательский клиент с авторизацией владельца через Telegram API/MTProto, например библиотека на основе TDLib после оценки runtime. Это отдельная сессия с существенными правами и возможностью отзыва. Источники: [Telegram APIs](https://core.telegram.org/api), [регистрация приложения](https://core.telegram.org/api/obtaining_api_id).

Сначала — разрешённое чтение выбранных диалогов/непрочитанных и короткая сводка; отправку включать отдельно. Полнота данных зависит от типа чата, доступности сессии и метода. Нельзя обещать все сообщения и secret chats как обычный облачный API. Для независимого фонового чтения при выключенных ПК адаптер должен работать в облаке; бесплатный serverless для него ещё не подтверждён.

## Яндекс Игры и другие кабинеты

Определить, какие показатели нужны, доступный официальный API/экспорт и права; при необходимости использовать разрешённый браузерный кабинет. Способ извлечения статистики ещё не исследован до конца. Сохранять источник, игру, период, валюту и свежесть; расчёты выполнять кодом, выводы модели маркировать как рекомендации.

Та же схема применяется к учёбе, продажам, календарю и будущим сервисам. Нет необходимости создавать отдельный «мозг» для каждого сайта.

## Критерии подключения

Явная авторизация аккаунта; минимальные scope; тест чтения на синтетических/разрешённых данных; отзыв сессии; цена и лимиты; дедупликация/пропуски; состояние «данные устарели»; prompt injection; документация. При выключенных устройствах сервис продолжает работу только если его адаптер реально запущен в облаке, а канал доставки подключён.
